# Browser Control MCP

[![Firefox Add-on](./.github/addon_badge.svg)](https://addons.mozilla.org/en-US/firefox/addon/browser-control-mcp/)

브라우저 확장과 짝을 이루는 MCP 서버입니다. AI 어시스턴트가 탭을 관리하고, 방문 기록을 검색하고, 웹 페이지를 읽고, **직접 클릭·입력·스크립트 실행까지 할 수 있게** 합니다.

기준으로 삼는 브라우저는 **[Zen Browser](https://zen-browser.app/)(Firefox 기반)**입니다.
확장 API가 Firefox의 것이라 Firefox에서도 그대로 돌아갑니다.

## 원본과 달라진 점

원본은 브라우저를 읽기만 하고 조작하지는 않습니다. 이 포크는 조작 기능을 더했습니다 — 클릭, 입력,
키 입력, 항목 선택, 스크롤, 그리고 페이지 안에서 임의의 JavaScript를 실행하는 기능입니다.
요소는 페이지 읽기에서 얻은
`ref`나 CSS 셀렉터로 지정합니다.

## 기능

MCP 서버가 제공하는 도구입니다.

**탐색과 읽기**

- 탭 열기 / 닫기
- `navigate-browser-tab` — 열려 있는 탭의 주소를 바꾸거나 방문 기록에서 앞뒤로 이동합니다.
  탭을 새로 열지 않고 하나를 계속 씁니다. 같은 출처의 주소는 먼저 페이지 자신에게 맡기므로,
  스스로 라우팅하는 앱은 다시 싣지 않고 상태를 유지합니다
- 열린 탭 목록 조회 (이 세션이 잡고 있는 탭 표시)
- `resize-browser-window` — 탭이 속한 창의 크기를 바꿉니다. 특정 너비에서 레이아웃 확인용
- `read-network-requests` — 페이지가 로드된 뒤 보낸 요청 목록: 메서드·URL·상태·소요 시간
- 이름과 색을 지정해 탭 그룹 만들기
- 탭 순서 바꾸기
- 방문 기록 읽기 및 검색
- `read-page` — 페이지의 본문과 상호작용 요소를 페이지에 놓인 순서 그대로 한 번에 읽기.
  요소마다 `ref`가 붙습니다 (페이지 전체, 또는 그 안의 한 요소만). 큰 페이지를 통째로 읽으면
  본문 대신 구역 개요가 오고, 각 구역의 `ref`로 그 부분만 읽습니다 — 내비게이션과 사이드바에
  토큰을 쓰지 않게. 구역은 다음 명령까지 화면에 상자와 라벨로 표시되며, 팝업의
  `대상 구역 표시`가 정한 크기 이상의 그룹에만 그립니다
- `find-text-in-page` — 페이지 안에서 텍스트를 찾아 강조하고, 매치를 담은 블록의 `ref`를 돌려줍니다
- 탭 화면 스크린샷 (보이는 화면 전체, 또는 그 안의 한 요소만) — 세로로 긴 요소는 여러 장으로
  나뉘고, 모든 캡처가 픽셀 크기와 바이트를 함께 보고합니다
- `list-page-media` — 페이지의 이미지·비디오·오디오를 URL·원본 크기와 함께 나열 (페이지 전체, 또는 한 요소 안만)
- `fetch-media-file` — 페이지가 보여 주는 이미지 파일을 페이지의 쿠키로 받아 옵니다
  (기본 꺼짐, `list-page-media`가 나열한 URL만 가능, Claude Code가 모델에 넘겨 주는 상한인 3.5MB까지)

**조작**

- `click-page-element` — 클릭 (더블 클릭, 가운데·오른쪽 버튼, 보조키 누른 채 클릭 포함)
- `hover-page-element` — 요소 위에 포인터를 올려 툴팁이나 메뉴를 드러냅니다
- `drag-page-element` — 요소를 끌어 다른 요소 위에 놓습니다
- `type-into-page-element` — 입력란에 텍스트 넣기, 폼 제출 또는 전송 버튼 클릭까지 한 호출로
- `press-key-in-tab` — Enter·Tab·Escape와 편집 단축키: `Ctrl+A`, `Ctrl+C`, `Ctrl+X`, `Ctrl+Z`,
  `Ctrl+Y`, 캐럿 이동 키, Backspace·Delete. `repeat`로 같은 키를 여러 번
- `scroll-browser-tab` — 위/아래/왼쪽/오른쪽/맨위/맨아래/특정 요소로 스크롤. 페이지 전체 또는
  페이지 안의 스크롤 요소
- `select-page-option` — `<select>` 항목 선택
- `upload-files-to-page-element` — 파일 입력란에 사용자 컴퓨터의 파일 첨부 (기본 꺼짐, 크기 한도는 팝업에서 설정, 기본 8MB)
- `run-browser-actions` — 여러 도구를 한 호출로 순서대로 실행, 첫 실패에서 멈춤
- `wait-for-page` — 셀렉터를 주면 요소가 나타나거나 사라질 때까지 대기. 셀렉터가 없으면
  페이지 텍스트가 바뀔 때까지 블로킹하고 새로 나온 부분만 반환. 지난 호출이 멈춘 자리에서
  이어받아 그 사이에 들어온 것도 놓치지 않습니다
- `execute-javascript-in-tab` — 페이지에서 임의의 JavaScript 실행

## 툴바 팝업

툴바 아이콘을 누르면 (또는 `Alt+Shift+B`) 팝업이 열립니다.

- **연결 상태** — 포트별 MCP 서버 연결 여부. 여기서 포트를 껐다가(이미 연결된 포트도 끌 수 있습니다)
  나중에 다시 켤 수 있습니다. 기준 포트도 여기서 정하며, 서버의 `EXTENSION_PORT`와 맞춰야 합니다.
- **권한** — 현재 탭, 권한 범위, 그리고 그 범위가 쓰는 목록을 보여 줍니다. 화이트리스트면 허용
  사이트 목록이, 블랙리스트면 차단 사이트 목록이 함께 표시됩니다. `+ 현재 탭`은 지금 보고 있는
  탭을 그 목록에 넣고, 목록은 한 줄에 하나씩 적는 텍스트 상자에서 고치면 바로 저장됩니다.
  화이트리스트에서는 탭이 이동하면 만료되는 일회성 허용을 쓸 수 있습니다.
- **새 탭** — 새 탭이 지금 보고 있는 탭의 컨테이너를 물려받을지 정합니다
- **상호작용 권한** — 스크린샷 / 마우스 / 키보드 / JavaScript / 미디어 파일 가져오기 개별 토글, 페이지가 감춰 둔 것까지 읽기·찾기·미디어
  목록에 실을지(개수는 항상 알려주고, 내용은 이 토글이 켜졌을 때만 hidden 표시로 실림), 그리고
  작업을 백그라운드에 둘지를 정합니다. 마지막 항목이 켜져 있으면(기본값) 새 탭이
  보고 있는 탭 뒤에서 열리고 페이지 내 찾기가 탭을 앞으로 끌어오지 않습니다. 스크린샷도 탭을 그대로
  둔 채 찍으며, 파이어폭스가 그 자리에서 찍기를 거부할 때만 탭을 앞으로 가져옵니다. 끄면 클릭과
  키 입력, 스크롤이 저마다 탭을 먼저 앞으로 가져오므로 작업하는 모습을 볼 수 있습니다.
- **표시** — 탭 아이콘 / 탭 오로라 / 동작 강조 / 상태 배지 네 가지를 각각 켜고 끕니다

### 권한 범위 2단계

| 모드                      | 동작                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **화이트리스트** (기본값) | 기본적으로 전부 막고, 허용 목록에 넣은 사이트와 팝업에서 직접 허용한 탭에서만 동작합니다. 탭 단위 허용은 탭이 이동하거나 닫히면 만료됩니다. |
| **블랙리스트**            | 차단 목록에 넣은 사이트를 뺀 모든 페이지에서 동작합니다.                                                                                    |

### 접근 허용 주소

모델이 열거나 이동할 수 있는 주소도 팝업에서 정합니다. 세 칸은 위험도 사다리입니다. 기본값
`HTTPS`는 그 밖의 주소를 전부 거절하고, `DEV`는 루프백 호스트의 `http://`를 함께 허용해
`http://localhost:5173/` 같은 로컬 dev 서버에 닿을 수 있게 하며, `HTTP`는 모든 http 주소를
허용합니다. `view-source:` 주소는 그것이 보여주는 문서로 판정합니다. `view-source:https://…`는
세 칸 모두에서 허용되고, `view-source:http://…`는 평범한 http와 같은 칸을 따릅니다.

그 외의 칸은 없습니다. 있어도 열릴 것이 없기 때문입니다. Firefox는 확장이 움직이는 탭을 특권
주소로 보내는 것 자체를 거절합니다. `chrome:`·`javascript:`·`data:`·`file:`과 특권 `about:`
페이지(`about:config`·`about:addons`·`about:debugging`·`about:newtab`)는 이 확장이 무엇을
허용하든 `tabs.update`와 `tabs.create` 안에서 `Illegal URL`로 실패합니다. `ftp://`는 Firefox
90에서 사라졌습니다.

이 설정은 `open-browser-tab`과 `navigate-browser-tab`에 적용되며, `list-page-media`와
`read-network-requests`가 돌려주는 주소도 같은 기준으로 걸러냅니다. 사용자가 직접 연 페이지는
영향을 받지 않으며, 위의 권한 범위를 그대로 따릅니다.

화이트리스트가 기본값인 것은 의도한 선택입니다. 확장을 넣자마자 모든 페이지가 뚫리는 대신,
사용자가 팝업에서 **명시적으로** 범위를 넓히게 했습니다.

`JavaScript` 도구도 같은 이유로 **기본이 꺼져 있습니다.** 가장 강력한 도구라 직접 켜야 합니다.

## 화면 효과

조작이 일어날 때 페이지 위에 오버레이가 그려집니다. 페이지의 DOM이나 CSS를 건드리지 않도록
Shadow DOM 안에 격리되며, 마우스 이벤트를 가로채지 않습니다. 네 가지를 팝업에서 각각 끌 수 있으니
거슬리는 것만 꺼 두면 됩니다.

- **탭 오로라** — 화면 테두리 안쪽에서 중앙을 향해 번지는 빛. 가로·세로 두 겹의 마스크로 중앙을
  지워 빛을 가장자리에만 남기므로 페이지 내용을 가리지 않습니다.
- **동작 강조** — 클릭·입력·스크롤 대상이 되는 요소 둘레의 테두리와 빛무리.
- **탭 아이콘** — 파비콘을 바꿔 탭 목록에서 조작 중인 탭을 알아볼 수 있게 합니다. 사이트가 페이지를
  이동할 때 자기 아이콘을 다시 지정하고 브라우저도 로드 뒤에 아이콘을 따로 받아오므로, 세션이 탭을
  잡고 있는 동안 두 경우 모두 표시를 다시 씌웁니다.
- **상태 배지** — 화면 위쪽 가운데에 지금 하는 동작을 알리는 작은 태그.

오버레이 색은 지금 하는 동작의 종류에 따라 바뀝니다. 오로라의 네 색을 포함해 모든 색과, 오버레이가
남아 있는 시간을 설정 페이지에서 바꿀 수 있습니다. 바꾸면 세션이 이미 잡고 있는 탭에도 곧바로
반영됩니다.

오버레이는 페이지에 주입한 DOM이라 탭이 다른 페이지로 이동하면 사라집니다. 세션이 그 탭을 잡고 있는
동안에는 새 문서 로드가 끝난 뒤 다시 그려집니다.

탭을 잡고 있는 것과 지금 동작하는 것은 서로 다른 시점에 끝납니다. 배지는 동작이 끝나면 곧 쉬는
문구로 돌아가지만, 탭을 잡고 있는 상태는 명령 사이의 긴 공백에도 풀리지 않습니다. MCP에는 턴이
끝났다는 통지가 없어서, 모델이 몇 분씩 생각해도 탭을 놓치면 안 되기 때문입니다. 이 상태는
`release-browser-tab` 도구, 탭 닫힘, 소켓 종료, 또는 명령 없이 90초가 지날 때 끝납니다. 이 길이는
옵션 페이지에서 바꿀 수 있습니다.

읽기는 예외로, 표시가 다음 명령이 올 때까지 그대로 남습니다. 다른 동작은 끝난 뒤에도 페이지에
흔적이 보이지만 읽기는 아무것도 바꾸지 않으므로, 그 표시가 읽었다는 사실을 알려주는 유일한
단서이기 때문입니다.

탭을 잡고 있는 동안에는 확장이 페이지의 `alert`·`confirm`·`prompt`를 대신 받습니다. 네이티브
대화상자는 페이지 스크립트를 멈춰 세워 이후 명령이 전부 시간 초과로 끝납니다. 그래서 확장은
대화상자가 뜨기 전에 대신 답하고, 페이지가 띄우려던 문구를 동작 결과에 실어 돌려줍니다.

`prefers-reduced-motion`이 켜져 있는 환경에서는 애니메이션이 멈춥니다. 스크린샷을 찍기 직전에는
오버레이를 지우므로 결과 이미지에 효과가 섞이지 않습니다.

스크린샷도 `ref`나 `selector`를 주면 그 요소만 잘라 찍습니다. 탭을 앞으로 꺼내지도, 페이지를
스크롤하지도 않습니다. 페이지 좌표로 잘라내므로 화면 아래로 넘어간 부분까지 한 장에 담기고, 둘레에
약간의 여백을 남깁니다. 2000픽셀보다 긴 요소만 잘린 채로 돌아오며, 이때는 스크롤 위치가 어느 구간을
찍을지 정합니다. 결과에 잘렸다는 사실과 요소의 전체 크기를 함께 적어 주므로 스크롤해서 나머지를
이어 찍을 수 있습니다.

## 사용 예시

### 탭 관리

- _"브라우저에서 업무와 관련 없는 탭을 전부 닫아줘."_
- _"개발 관련 탭을 모아서 'Development' 그룹으로 묶어줘."_
- _"24시간 동안 안 본 탭을 전부 닫아줘."_

### 방문 기록 검색

- _"방문 기록에서 뉴질랜드 밀포드 트랙에 대한 글을 찾아줘."_
- _"지난주에 본 AI 관련 글을 중복 없이 10개까지 열어줘."_

### 조사와 조작

- _"해커뉴스를 열고 인기 글과 댓글을 읽어줘. 댓글이 본문에 동의하는 편이야?"_
- _"구글 학술검색에서 최근 3년간 L-테아닌 논문을 찾고, 인용 많은 3편을 열어서 요약해줘."_
- _"이 페이지의 로그인 폼에 아이디를 넣고 제출해줘."_
- _"검색창에 '오로라'를 입력하고 엔터를 눌러줘. 결과가 뜨면 첫 번째 항목을 클릭해."_

## 보안에 대해

이 포크는 원본이 막아 둔 기능을 여는 것이 목적이므로, 원본보다 **덜 안전합니다.**

**그대로 유지되는 것**

- MCP 서버와 확장 사이는 로컬 연결이고, 공유 비밀 키로 서명해 인증합니다.
- 원격 수집이나 추적이 없습니다.
- 확장에는 런타임 서드파티 의존성이 없습니다.
- 모든 도구 호출이 확장 쪽 사용 기록(감사 로그)에 남습니다. 신규 조작 도구도 포함됩니다.
- 도구별 토글이 그대로 남아 있고, 조작 도구 3종이 여기에 추가되었습니다.
- 차단 목록은 권한 범위와 무관하게 **언제나** 적용됩니다.

**달라진 것 — 여기가 중요합니다**

- 페이지 조작과 임의 스크립트 실행이 가능해졌습니다. 켜져 있는 동안 MCP 서버는 사용자가 로그인한
  상태 그대로 무엇이든 누르고 입력할 수 있습니다.
- **호스트 권한 `<all_urls>`가 필수 권한입니다.** 원본은 도메인마다 사용자에게 물었지만, 이 포크는
  확장 로드 시점에 전체 웹 접근 권한을 받습니다. 즉 **브라우저가 도메인마다 받쳐 주던 방어선이
  없습니다.** 권한 범위와 도구 토글, 즉 이 확장의 코드가 유일한 방어선입니다.
- `execute-javascript-in-tab`은 확장의 content script 샌드박스에서 실행됩니다. DOM은 전부 보이지만
  페이지 자체의 JavaScript 전역은 `window.wrappedJSObject`를 거쳐야 보입니다.

**왜 이렇게 했나** — 도메인마다 승인 창이 뜨면 실사용이 불가능합니다. 대신 방어선을 확장 안으로
옮기고, 기본값을 잠긴 쪽(화이트리스트 + JS 꺼짐)에 두어 사용자가 명시적으로 열게 했습니다.

**권장 설정** — 평소에는 **화이트리스트**로 두고 필요한 탭만 팝업에서 허용하세요. 작업이 많아지면
블랙리스트로 바꾸고, 작업이 끝나면 되돌리는 편이 낫습니다. 이상하다 싶을 때 팝업의 상호작용 토글
3개를 끄면 조작 권한이 즉시 사라집니다.

**주의**: Browser Control MCP는 아직 실험적입니다. 다른 MCP 서버와 마찬가지로 도구 호출을 주의 깊게
확인하며 사용하세요. 사용에 따른 책임은 사용자에게 있습니다.

## Zen Browser에 대해

- **컴팩트 모드**에서는 툴바가 숨겨져 아이콘이 안 보일 수 있습니다. 이때는 `Alt+Shift+B`로 팝업을 엽니다.
- **분할 화면(Split View)**에서는 `captureVisibleTab`이 창의 보이는 영역을 통째로 찍으므로 스크린샷에
  두 탭이 함께 담깁니다.

- **워크스페이스와 컨테이너** — Zen은 워크스페이스를 컨테이너(userContext)에 묶을 수 있습니다.
  컨테이너마다 쿠키 저장소가 따로라, 새 탭을 기본 컨테이너에 열면 **로그인이 풀린 것처럼 보입니다.**
  그래서 `open-browser-tab`은 기본적으로 **지금 보고 있는 탭의 컨테이너를 물려받습니다.**
  직접 새 탭을 여는 것과 같은 결과입니다.

  **팝업의 "새 탭 → 로그인 세션 유지" 토글**이 평소 동작을 정합니다(기본 켜짐). 팝업의 "현재 탭"
  칸에 지금 어느 컨테이너에 있는지도 표시됩니다.

  ```
  open-browser-tab(url, container="auto")     ← 기본값. 팝업 토글을 따름
  open-browser-tab(url, container="inherit")  ← 토글과 무관하게 현재 컨테이너 강제
  open-browser-tab(url, container="default")  ← 브라우저 기본 컨테이너. 보통 로그아웃 상태
  open-browser-tab(url, container="<cookieStoreId>")  ← 특정 컨테이너 지정
  ```

  즉 **팝업 = 평소 기본 동작, 도구 파라미터 = 그 호출만의 예외**입니다.
  `list-open-tabs`가 탭마다 `container=`를 함께 알려 주므로 특정 컨테이너를 골라 열 수 있습니다.

## 설치

> **주의**: [addons.mozilla.org의 배포판](https://addons.mozilla.org/en-US/firefox/addon/browser-control-mcp/)과
> 원본 저장소의 릴리스(`.xpi`, `.dxt`)는 **원본**입니다. 이 포크의 조작 기능·팝업·오버레이가
> 들어 있지 않으니, 아래처럼 **코드에서 직접 빌드**하세요.

### 1. 빌드

저장소를 클론한 뒤 루트에서 아래를 실행하면 MCP 서버와 확장이 모두 빌드됩니다.

```
npm install
npm run build
```

### 2. 확장 로드

1. 주소창에 `about:debugging` 입력
2. "이 Firefox" 클릭
3. "임시 부가 기능 로드..." 클릭
4. 이 프로젝트의 `firefox-extension` 폴더에 있는 `manifest.json` 선택
5. 설정 페이지가 열립니다. 비밀 키를 펼쳐서 복사해 두세요. MCP 서버 설정에 씁니다.

Zen Browser에서도 `about:debugging` 경로가 같습니다. 임시 부가 기능은 브라우저를 다시 켜면
사라지므로, 껐다 켤 때마다 다시 로드해야 합니다.

개인 브라우저에서 돌리기가 꺼려진다면 별도의 Firefox 인스턴스(예:
[Firefox Developer Edition](https://www.mozilla.org/en-US/firefox/developer/))를 쓰는 방법도 있습니다.

#### zip으로 묶기

저장소 루트에서 실행합니다.

```
npm run package
```

`firefox-extension/web-ext-artifacts/browser_control_mcp-<버전>.zip`이 만들어집니다. `about:addons`
에서 톱니바퀴를 누르고 "파일에서 부가 기능 설치..." 로 그 zip을 고르면 됩니다. 브라우저를
껐다 켜도 남아 있으므로 위의 2번 단계는 필요 없습니다.

Zen Browser에서는 동작을 확인했습니다. 일반 Firefox에서도 되는지는 확인하지 못했습니다.

### 3. MCP 서버 연결

#### 가장 쉬운 방법: `setup.ps1`

저장소 루트에서 아래를 실행합니다. 물어보는 것은 모두 Secret Key 앞에서 끝납니다. 언어를 고르고,
찾지 못한 것을 설치할지 답하면, 두 클라이언트의 상태를 한 번에 보여주고 앞으로 무슨 일이 일어날지
알린 뒤 키를 받습니다. 키를 넣은 다음부터는 멈추지 않고 끝까지 갑니다. 의존성 설치, 빌드, 등록,
Desktop 설정 파일 기록, 확장 zip 패키징까지 한 번에 진행합니다. 새 Secret Key를 발급했을 때 다시
실행하면 됩니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

```
Language / 언어  [1] English  [2] 한국어

  빌드를 확인하는 중

  빌드             MCP 서버와 확장이 준비돼 있습니다

  클라이언트를 찾는 중

  Claude Code      MCP 서버가 등록돼 있습니다, Secret Key 를 갱신합니다
  Claude Desktop   앱은 있으나 MCP 서버가 등록돼 있지 않습니다, 새로 등록합니다
                   설정 파일: C:\Users\me\AppData\Local\Packages\Claude_…\LocalCache\Roaming\Claude\claude_desktop_config.json

Secret Key
```

`y/N`로 답하기 전에는 아무것도 설치하지 않고, 단계마다 무엇을 할 것인지 먼저 알려 줍니다.

아래는 직접 명령을 넣고 싶을 때의 설명입니다.

#### Claude Code에서 쓰기

Claude Code는 DXT를 쓰지 않습니다. 아래 한 줄이면 됩니다.

```
claude mcp add browser-control \
  --env EXTENSION_SECRET=<SECRET KEY> \
  -- node /path/to/repo/mcp-server/dist/server.js
```

프로젝트 단위로 두고 싶으면 저장소 루트의 `.mcp.json`에 같은 내용을 적어도 됩니다.

```json
{
  "mcpServers": {
    "browser-control": {
      "command": "node",
      "args": ["/path/to/repo/mcp-server/dist/server.js"],
      "env": {
        "EXTENSION_SECRET": "<SECRET KEY>"
      }
    }
  }
}
```

#### Claude Desktop에서 쓰기

`claude_desktop_config.json`에 위와 같은 `mcpServers` 항목을 추가합니다.

`/path/to/repo`를 실제 경로로 바꾸고, `EXTENSION_SECRET`에는 확장 설정 페이지에 표시된 값을 넣습니다.
필요한 변수는 그것 하나뿐입니다. 기준 포트는 8089가 기본값이고, `EXTENSION_PORT`는 그 값을
8089가 아닌 것으로 바꿀 때만 씁니다.

MCP 서버가 확장에 연결되기까지 몇 초 걸릴 수 있습니다. 팝업의 연결 상태에서 확인할 수 있습니다.

#### 세션을 여러 개 열어도 됩니다

Claude 세션마다 MCP 서버 프로세스가 하나씩 뜨는데, TCP 포트는 한 프로세스만 잡을 수 있습니다.
그래서 서버는 **기준 포트(8089)부터 위로 올라가며 빈 포트를 잡고**, 확장은 **연결된 가장 높은
포트보다 한 칸 위에 항상 예비 슬롯을 하나 열어 둡니다.**

```
세션 1 → 8089 ┐
세션 2 → 8090 ├→ 확장 (포트마다 독립 핸들러)
세션 3 → 8091 ┘
        8092  ← 다음 세션을 기다리는 예비 슬롯
```

세션이 늘면 포트도 따라 늘고, 세션이 끝나면 남는 슬롯은 회수됩니다.

#### DXT 패키지가 필요한 경우

DXT는 Claude Desktop이 MCP 서버를 한 번에 설치하게 해 주는 포장 형식입니다.
**Claude Code에는 필요 없습니다.** Claude Desktop에 클릭 한 번으로 설치하고 싶을 때만 만드세요.

```
cd mcp-server
npm run pack-dxt
```

`mcp-server/manifest.json`이 DXT 매니페스트입니다. 원본 저장소가 릴리스한 `.dxt`에는 조작 도구가
없으니 반드시 직접 빌드한 것을 쓰세요.

## 개발

```
npm install                          # 하위 프로젝트 의존성까지 설치
npm run build                        # nx로 전체 빌드
cd firefox-extension; npm test       # 확장 테스트
cd mcp-server; npm start             # MCP 서버 실행
npm run package                      # 설치용 확장 zip 생성
```

UI 문자열은 `firefox-extension/_locales/{en,ko}/messages.json` 에 있습니다. `default_locale` 이
`en` 이라 한국어 브라우저에서 찾지 못한 항목은 영어로 대체됩니다.
